# Profile: reference-manual

## Signals
- "Reference Manual", "User's Manual", "Programmer's Guide", "Technical Reference", "Operating Instructions"; chapters on installation, configuration, commands, registers, error codes.
- Long documents with a table of contents, index, appendices, revision history.

## Typical content
- Register maps and bit fields, command sets and syntax, memory maps, configuration tables.
- Procedures (numbered steps), menus and screens, error/status code lists, examples and code listings.
- Appendices: character sets, tables, glossaries.

## Custom steps
- **Stage 2:** use the table of contents and bookmarks to build the page content map; ask whether all chapters are needed (installation and safety chapters are often skipped on request).
- **Stage 4:** command syntax in code blocks with parameter tables; keep examples exactly, including prompts and whitespace. Numbered procedures stay numbered lists. Screenshots of text screens become text screens; real photos follow the photo rule.
- **Stage 4:** register maps as tables with address, name, access, reset value and fields; cross-reference field descriptions.
- **Stage 5:** check that every command or register named in the overview has a section.
- **Stage 7:** split by chapter groups aligned with tasks (setup, operation, programming reference, error handling, appendices).
- **Stage 8:** command index, register quick map, error-code table, glossary.

## Questions to ask
- Which chapters matter (all, programming only, a subsystem)?
- Should code examples be tested or only transcribed? (Default: only transcribed.)

## Split suggestion
- Overview and setup; operation; command reference; register reference; errors and troubleshooting; appendices.

## Useful extras
- Command index with one-line descriptions; register quick map; error-code lookup; glossary.
