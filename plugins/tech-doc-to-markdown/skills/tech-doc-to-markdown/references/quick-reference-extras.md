# Quick-Reference Extras

Derived aids that let a later session answer common questions without re-reading the transcription. Add them only when the user selected extras.

## Rules

- **Derived only.** Every value comes from the transcription. Name the source section or page for each block.
- **Label the kind of content:** *derived* (computed from printed values), *inferred* (interpretation the document does not state), *design choice* (values you picked for a worked example).
- **Never contradict the body.** If you find an inconsistency while building an extra, add it to the inconsistency list and a Transcriber's note in the body.
- **Placement:** a `## Quick reference` section at the end of a single-file transcription, or its own part (`<prefix>-10-quick-reference.md`) after a split, linked from the index.

## Candidates by document type

| Aid | Typical documents | Content |
|---|---|---|
| Byte / code decode map | Controllers, protocols | Value ranges and what each means (for example `00h-7Fh display character, 80h-BFh field attribute ...`) |
| Command cheat sheet | Controllers, peripherals, instruments | Command, byte/opcode, parameters with direction and count, effect, status flags touched |
| Register quick map | Microcontrollers, peripherals | Address, name, access, reset value, fields |
| Consolidated timing table | Anything with A.C. characteristics | Symbol, name, min, typ, max, unit, condition, waveform, measured-from edge, to edge; parameters drawn but not tabulated marked "no value in tables" |
| Formulas | Timing, clocks, geometry, analog | Frame/line/character timing, dividers, gain, cutoff; each with units and source values |
| Worked configuration example | Programmable devices | A realistic setup computed step by step; design choices labelled; resulting bytes and derived timing |
| Pin list by function | ICs, connectors | Groups (bus, clock, power ...) with pin numbers, direction, active level |
| Glossary | All | Abbreviations as defined in the document; mark any expansion that needs outside knowledge |
| Known inconsistencies | All | Numbered list of contradictions, typos, drawing oddities and ambiguous numbering, each with location |
| Programming/usage checklist | Programmable devices, procedures | Ordered steps and cautions gathered from notes (power-up rules, required dummy bytes, limits) |
| Machine-readable tables | When a consumer exists (driver, emulator, test script) | YAML/CSV generated by script from the Markdown tables, with `derived` flags; skip unless there is a concrete use |

## Worked-example template

```markdown
### Worked example: <goal> (derived; design choices marked)

| Step | Field | Value | Bits | Source |
|---|---|---|---|---|
| 1 | Characters per row | 80 → H = 79 | `1001111` | Reset byte 1 table |
| 2 | Vertical retrace rows | 2 *(design choice)* → V = 01 | `01` | Reset byte 2 table |

Resulting bytes: `4Fh 58h 99h C7h` (derived).
Derived timing at the tCLK limit of 480 ns: ... (derived).
Assumptions: <inferred readings, e.g. 0-based underline numbering>.
```

## Inconsistency list template

```markdown
### Known inconsistencies in the source

1. **<short name>** (page <n>): the original prints <X>; <Y> elsewhere says <Z>. The transcription keeps <X> and notes it in <section>.
```
